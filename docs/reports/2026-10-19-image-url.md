# 完整報告：支援圖片網址訊息

日期：2026-10-19　分支：`feat/image-url`（從 main 的 de0befd 分出）

## 需求摘要

使用者在 Pi 上實測時發現，圖庫頻道裡有一些舊訊息是「圖片網址＋文字」（例如 `mygo、我早就知道會這樣了\nhttps://i.imgur.com/jgoYzsS.jpg`），用 `/search` 怎麼搜都找不到。

**原因**：舊訊息只有帶圖片附件的才會收進索引（`internal/index/scan.go` 用 `recognize.Eligible` 判斷）。網址訊息沒有附件，所以被跳過。原本規劃的「貼圖片連結的訊息不處理」只針對自動處理，卻同時影響了舊訊息的搜尋。

**新需求**

- 舊訊息中的圖片網址要能搜尋。比對和提示文字去掉網址；`/search` 選到時**直接貼出網址**，但貼出前要先確認圖片還在。
- 以後在圖庫頻道貼的圖片網址，要下載下來走辨識流程，重新上傳成「圖片＋圖片訊息」，再刪除原訊息。

[docs/plans/2026-10-19-image-url.md](../plans/2026-10-19-image-url.md)，共 7 個任務。文末記錄了使用者在 U1～U12 與各輪把關後做的決定。

## 把關者提出的問題與處理結果

這一批共把關 6 次。前 3 次是同一批修正的來回，第 2、3 次被退回，第 4 次通過；之後兩個小批次各把關 1 次，都通過。

| 輪次 | 結果 | 必修問題與處理 |
|---|---|---|
| 1 | 通過 | 建議：封鎖 IPv6 過渡位址、url_since 改用 Discord 時間（Pi 沒有 RTC）、重讀與刪除的競爭、Check 加逾時 → 全部修正 |
| 2 | 退回 | `Check` 把 SVG 和非點陣圖內容當成「確定是圖片」，可以繞過防釣魚規則 → 改成只有 PNG/JPEG/GIF/WEBP 才算確定是圖片 |
| 3 | 退回 | (1) 重複的 Content-Type 標頭可以繞過（Go 取第一個值、瀏覽器取最後一個）→ 檢查全部值；(2) 用 octet-stream 送出的 SVG 被誤判為確定不是圖片 → 依使用者決定 (b)，歸為無法確認 |
| 4 | 通過 | 建議：Refresh／attachment 下載成非圖片檔名，使用者決定要擋；Fetch 遇到無法確認的放行交給解碼；未解壓的編碼歸為無法確認 → 已做 |
| 5、6 | 通過 | `filename*` 不是 UTF-8、非 inline 的未知 disposition → 歸為無法確認 |

把關者試過的繞過手法包括：IP 的各種寫法、IPv4-mapped IPv6 與 IPv6 過渡位址、DNS rebinding、轉址、帶帳密的網址、gzip 炸彈、polyglot 檔案、Content-Type 的大小寫、逗號、重複寫法、SVG 的各種寫法、Content-Disposition 的各種寫法、偽造的 Key、偽造的 embed，最後都被擋下。

**已接受的已知限制**

- 依 UA／IP 回不同內容的釣魚伺服器無法防範（使用者接受）。
- 少見寫法的 SVG（開頭是註解或 DOCTYPE、UTF-16）會被移除索引，但不會被貼出。
- 需要 Referer 或登入的圖床、已過期的 Discord 附件連結無法下載。
- trace.moe 匿名每月額度 100 次（`/me` 查詢結果），每個 IP 一次只能查一張。

**建議之後清理**：`snowflake.FromTime`、`index.UpdateLegacyText` 已經沒有正式程式使用。

### 需要在 Pi 上實測

1. 第一次啟動：log 顯示 url_since；儲存頻道多兩則版本；`/storage show` 看得到；再次重啟不會重寫。
2. `/search mygo`、`/search 放棄`：找得到，提示文字不含網址；貼出的訊息只有網址，而且有預覽。
3. 編輯舊訊息：把網址刪掉後搜尋不到；只改文字時，搜尋結果跟著更新。
4. 新貼 `.jpg` 網址＋文字：發出圖片訊息、刪除原訊息，關鍵字不含網址。
5. 新貼沒有副檔名、但 Discord 顯示成圖片的網址：約 5 秒後處理，而且只處理一次。
6. 把純文字訊息編輯成加上圖片網址：會被處理。
7. 一般網頁連結、gifv：不處理，也不加 ⏳／❌。
8. 已刪除的 imgur 網址：加 ❌；對它「重新辨識」回「重新處理失敗」。
9. 劇透網址：重新上傳時保留劇透；`/search` 貼出 `||網址||`。
10. `/search` 遇到已刪除的網址：回「圖床上的圖片已被刪除，無法貼出」，並從索引移除。遇到回 403 的圖床：有預覽就貼出，否則回「目前無法確認圖片，請稍後再試」。
11. 多張大網址圖時的記憶體用量。

## 使用者在過程中做的決定

- **舊訊息**：圖片網址收進搜尋，比對和提示去掉網址；每個網址算一張；`/search` **直接貼出網址**，但要先檢查圖片還在。
- **新訊息**：下載網址的圖並走辨識流程，重新上傳後刪除原訊息；下載失敗就一張都不發、加 ❌。
- **U1 選 (b)**：記錄「圖片網址功能上線時間點」。在這之前的只含網址訊息只收進搜尋，不處理、不刪除。
- **U2～U7 照建議**：編輯加上網址也處理；gifv 不處理；網頁預覽改下載預覽中的圖；AVIF／SVG 等算不是圖片；同一個網址只算一次；三種包裝寫法都算。
- **`/search` 的檢查與防釣魚**：
  - 只有確定已刪除（404／410／imgur removed.png）或確定不是圖片時才擋下並移除索引；其他錯誤只有在 Discord 有圖片預覽時才貼出。
  - SVG 等非點陣圖歸為無法確認：沒有標 Content-Type 的 SVG 算無法確認，HTML 仍算不是圖片。
  - 帶 Refresh 或「下載成非圖片檔名」的回應歸為無法確認。
- 只剩 gifv 的 ❌ 訊息「重新辨識」回「這則訊息沒有可處理的圖片」，不加回 ❌。
- 接受「依 UA／IP 回不同內容的釣魚伺服器無法防範」為已知限制。
- 文字：「圖床上的圖片已被刪除，無法貼出」「目前無法確認圖片，請稍後再試」「這則訊息沒有可處理的圖片」。
