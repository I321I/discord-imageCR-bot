# 動畫截圖圖庫 bot 實作規劃

> **給實作者：** 依 `superpowers:test-driven-development` 逐項實作，步驟用 `- [ ]` 追蹤。依專案規則，實作者不 commit；每個「交付點」由 PM 決定是否 commit（見待決定問題 Q8）。

**目標：** 把現有只會記住頻道的 bot，改成「圖片來源頻道自動整理圖片＋辨識作品與字幕＋右鍵修改＋跨伺服器 `/search`」，設定存在 Discord 儲存頻道，用 Docker 部署。

**架構：** `bot.go` 只負責讀設定、建立 session、接線。功能拆成 `internal/` 下的小套件，每個套件只依賴「自己定義的小介面」（Discord、HTTP、trace.moe、OCR、時鐘），`*discordgo.Session` 與 `*discordgo.State` 直接滿足這些介面；測試一律用假實作，`go test ./...` 不連網、不需要 Tesseract。

**技術：** Go（go.mod 為 `go 1.24.13`）、discordgo v0.29.0、godotenv、`golang.org/x/image/webp`（新依賴，解 WEBP）、Tesseract 命令列、trace.moe REST API、Docker。

**設計文件：** `docs/superpowers/specs/2026-10-12-image-bot-design.md`（實作者兩份都要讀）

**標記說明：** 文中 `Q數字` 指本檔最後「待決定問題」。標了 Q 的地方在使用者回答前**不得實作**；回答後 PM 會把答案填回本檔或附在派工訊息中。

## 全域限制

- 全部免費：不得引入付費 API。
- 辨識失敗標記字串固定為 `⚠️ 辨識失敗`。
- 圖片訊息欄位順序：作品、圖片文字、角色、關鍵字；留空欄位放最後；最後一行 `上傳者：<@userID>`，不可編輯、不參與搜尋。
- 多值分隔一律輸出「、」；圖片文字不拆分，多句用換行。
- 處理的附件類型：PNG、JPG、WEBP、GIF（GIF 用第一格）。訊息含任何非圖片附件 → 整則不處理不刪除；只有連結/embed 不處理；純文字不處理。
- 全部辨識完成才發圖片訊息；每張圖一則；重新上傳檔案；全部發完才刪原訊息。
- 設定只能存成 Discord 訊息（JSON，>2000 字拆多則），不得寫檔。
- 不得覆蓋使用者已填資料（重新辨識只動失敗欄位）。
- 可用頻道 = 被設為來源 ∧ 使用者是該伺服器成員 ∧ 使用者對該頻道有 View Channel（含身分組與頻道覆寫）。套用在 `/search`、勾選指令、右鍵指令。
- 不開 Server Members 特權 intent；Intents 為 `IntentsGuilds | IntentsGuildMessages | IntentsMessageContent`。
- 成員查詢快取 key（guildID, userID），404 也快取，mutex 保護，預設 5 分鐘（Q49）。頻道可見性不快取，用 gateway state 現算。
- 新環境變數 `STORAGE_CHANNEL_ID`（必填）。
- OCR 語言 `chi_tra+chi_sim+jpn+eng`；OCR 必須是可替換介面。
- trace.moe 請求要排隊（並行數 1）。
- 每次執行 `go build ./...`、`go vet ./...`、`go test ./...` 都要通過。

## 把關重點（Review Focus）

測試未必能自然覆蓋、但最容易傷到使用者的情況，各自已在負責的任務加上釘住它的測試：

1. **圖片遺失**：多張圖中任一張下載/辨識/發送失敗，或刪原訊息失敗時，原圖不能消失（Task 5.2 `TestProcess_SendFailure_KeepsOriginal`）。
2. **覆蓋使用者資料**：使用者編輯與「重新辨識」同時發生時，重新辨識不能把使用者剛填的欄位蓋掉（Task 8.2 `TestRerecognize_MergesIntoLatestContent`）。
3. **繞過權限**：`/search` 送出的值是 client 傳來的字串，可被偽造；送出時要重新檢查頻道可用（Task 9.2 `TestSearchSubmit_RejectsUnavailableChannel`）。
4. **啟動讀設定失敗後被空資料覆蓋**：讀取失敗不可接著寫入空資料（Task 1.3 `TestLoad_ErrorDoesNotAllowSave`）。
5. **非指令類 interaction 造成 panic**：現有 handler 對所有 interaction 呼叫 `ApplicationCommandData()`，modal / component / autocomplete 會 panic（Task 2.1 `TestRouter_DispatchesByInteractionType`）。

其他風險（給把關者）：

- **並行**：discordgo 每個事件開 goroutine，`store`、`index`、成員快取一定要上鎖，測試用 `go test -race`。
- **圖片訊息解析**：OCR 文字裡若出現「角色：」等開頭的行，解析會切錯欄位（Task 3.1 `TestParse_TextContainingLabelLikeLine` 規定只認「行首的已知標籤且順序在後」）。
- **2000 字上限**：Format 結果必須 ≤ 2000 字（Q23）。
- **autocomplete 3 秒**：未快取伺服器的成員查詢要並行且有截止時間（Q51）。
- **CDN 連結過期**：索引不存附件 URL，貼圖前重新抓訊息取得新 URL。
- **`discordgo.memberPermissions` 未匯出**：v0.29.0 沒有公開的 `MemberPermissions`，需自行移植權限計算（Task 7.1）。
- **全域指令**：使用者安裝指令只能全域註冊，全域指令傳播較慢；不要在關機時刪掉（Q2）。

## 階段 3：圖片訊息格式（純函式）

### Task 3.1：格式化、解析、正規化

**Files:** Create `internal/imagemsg/imagemsg.go`、`imagemsg_test.go`

**Produces:**
```go
const FailedMarker = "⚠️ 辨識失敗"
type Field int // FieldWork, FieldText, FieldCharacters, FieldKeywords
type Fields struct { Work, Text, Characters, Keywords string }
func Format(f Fields, uploaderID string) string
func Parse(content string) (f Fields, uploaderID string, ok bool)
func NormalizeList(s string) string       // 分隔符號集合依 Q22；trim、去空值、（是否去重依 Q22）、以「、」連接
func (f Fields) Failed() []Field          // 值 == FailedMarker 的欄位
func (f Fields) Get(Field) string; func (f *Fields) Set(Field, string)
func Label(Field) string                  // "作品" "圖片文字" "角色" "關鍵字"
```

規則：
- 每欄一行 `標籤：值`；`Text` 可多行，續行接在其後。非空欄位依固定順序在前、空欄位依固定順序在後；最後 `上傳者：<@id>`。

- 2000 字上限的截斷策略依 Q23。

- **Q15 trace.moe 相似度門檻**：低於門檻視為辨識失敗。｜太低會填錯作品，太高會很多失敗。｜建議：0.90（trace.moe 官方說明低於 0.9 的結果多半不正確）。
